# CCA-F 视频课程 · 设计与制作方案

配套 `/learning/ccaf-quest`。每个任务一条 1–2 分钟短视频，可嵌进任务对话框当「讲解」按钮。

---

## 1. 核心约束：Veo 一次只能生成 8–30 秒

这是硬限制，不能绕过，只能**设计成不需要绕过**。

关键决定：**把「时长的不确定性」放在免费的地方。**

| 素材类型 | 时长 | 成本 | 能不能画准架构图 |
|---|---|---|---|
| Veo 片段 | 8 秒，固定 | 贵、慢 | ❌ 文字会糊，图会错 |
| 代码渲染动画 | 任意长度 | 几乎免费 | ✅ 完全可控 |
| 3D 城市实录 | 任意长度 | 免费（已有） | ➖ 只适合做场景 |

所以时间轴的结构是：**Veo 片段是固定长度的「卡槽」，代码动画是可伸缩的「填充物」**。旁白多说 5 秒，就让代码动画多播 5 秒——Veo 片段一帧都不用重生成。

一条 90 秒的课这样排：

```
0:00 ─ 0:08   [Veo]     开场氛围镜头（信号房外景，霓虹，雨夜）      8s 固定
0:08 ─ 0:35   [diagram] 问题：循环怎么知道该停                    27s 弹性
0:35 ─ 0:43   [Veo]     转场（信号灯从红跳到绿）                   8s 固定
0:43 ─ 1:18   [compare] 三种做法对比 → 正解                       35s 弹性
1:18 ─ 1:30   [card]    考点卡片 + 「去做这道题」                  12s 弹性
```

固定部分永远是 8 的倍数，其余全部由旁白长度决定。

## 2. 第二个核心原则：音频是时钟

**先生成配音，量出真实时长，再排时间轴。** 不要先定视觉时长再配音——那样旁白必然对不上画面，而且每改一句话就要重排。

顺序是不可颠倒的：

```
剧本 → TTS 生成音频 → 读取每段音频的真实毫秒数 → 用这些数字排时间轴 → 渲染
```

中英文同一段话时长差异很大，所以**中英文是两条独立的时间轴**，共用同一套视觉素材和同一批 Veo 片段。这也是为什么 Veo 片段必须是「无文字」的纯氛围镜头——只有这样才能两种语言复用，成本减半。

**实测数据（第 1 课，6 个声音取平均）**：英文 56.2 秒，中文 63.8 秒——**中文比英文长约 14%**。
这和「中文更精简」的直觉相反，原因是我们的中文旁白写得更展开。这正说明时长必须实测、
不能估：如果按英文时间轴去铺中文，每一课都会超时 7 秒以上。

## 3. 制作流水线

```
  ccafMissions.ts（已有的 45 个任务）
        │
   [1] 剧本生成（Gemini）
        │  输入：任务题目 + 选项 + 解析 + 考点
        │  输出：ccafVideoLessons.ts —— 分镜脚本，中英双语
        ↓
   [2] 配音（Vertex TTS Chirp3-HD）── 6 个声音，用户可选
        │  输出：每个 beat 一个 mp3 + 精确时长（ms）
        ↓
   [3] 排时间轴 ── 用真实音频时长把 beats 铺开
        │  Veo 槽位对齐到 8s 边界，代码动画吸收余量
        ↓
   [4a] Veo 片段生成（只做氛围镜头，无文字）
   [4b] 代码动画渲染（架构图 / 代码高亮 / 对比）
   [4c] 3D 城市实录（可选，复用现有场景）
        ↓
   [5] 合成 ── 视频轨 + 音频轨 + 字幕轨 → 单个 MP4
        ↓
   [6] 上传 Firebase Storage + 写 manifest 到 Firestore
```

第 4a 和 4b 可以并行；Veo 是最慢的一环，先跑。

### 增量重跑

每个 beat 记录一个内容哈希。改一句旁白只重跑那一个 beat 的 TTS 和那一段动画，Veo 片段和其他 beat 全部命中缓存。**改文案不该花钱重生成视频。**

## 5. 配音：6 个声音

Vertex AI TTS 的 **Chirp3-HD** 系列，中英文都有高质量拟真声线。

| | 英文 | 中文 |
|---|---|---|
| 男 1 · 稳重讲师 | `en-US-Chirp3-HD-Charon` | `cmn-CN-Chirp3-HD-Charon` |
| 男 2 · 年轻干练 | `en-US-Chirp3-HD-Puck` | `cmn-CN-Chirp3-HD-Puck` |
| 男 3 · 低沉叙述 | `en-US-Chirp3-HD-Enceladus` | `cmn-CN-Chirp3-HD-Enceladus` |
| 女 1 · 清晰明亮 | `en-US-Chirp3-HD-Zephyr` | `cmn-CN-Chirp3-HD-Zephyr` |
| 女 2 · 温和亲切 | `en-US-Chirp3-HD-Aoede` | `cmn-CN-Chirp3-HD-Aoede` |
| 女 3 · 冷静专业 | `en-US-Chirp3-HD-Kore` | `cmn-CN-Chirp3-HD-Kore` |

具体可用声线以调用 `voices.list` 的返回为准，上表是目标风格映射。

**成本上的取舍：** 6 声音 × 2 语言 × 45 课 = 540 条完整配音。如果全部预生成，视频也要出 12 个版本，存储和渲染都翻 12 倍。

建议改成：**视频只渲染一个「默认声音」版本，其余 5 个声音走「音轨切换」**——播放器加载同一个静音视频 + 用户选的那条音轨。视频只存 2 份（中/英），音频存 12 份（小得多）。用户切声音是瞬时的，不用重新缓冲视频。

### 第 1 课分镜（模板，其余 12 课同构）

**看信号 / Read the Signal** — 90s

| 时间 | kind | 画面 | 旁白（中文） |
|---|---|---|---|
| 0:00–0:08 | `veo` | 雨夜，信号房外的红绿灯在闪 | — （环境音 + 标题动画） |
| 0:08–0:30 | `diagram` | 循环图：模型 → 工具 → 结果 → 回到模型，转个不停 | 「你写了一个会调用工具的 agent。它跑起来了——问题是，它怎么知道该停？」 |
| 0:30–0:38 | `veo` | 信号灯从红跳到绿，特写 | — |
| 0:38–1:10 | `compare` | 左：解析文本找「我做完了」（打叉）／ 中：固定轮数（打叉）／ 右：`stop_reason` 分支（打勾） | 「三种做法。第一种去读模型说了什么——但措辞每次都不一样。第二种数轮数——够用的轮数会把剩下的任务砍在半路。真正的答案在 API 本来就返回的字段里。」 |
| 1:10–1:22 | `code` | 循环代码，`stop_reason === 'tool_use'` 高亮 | 「`tool_use` 就执行工具、继续循环。`end_turn` 就收工。迭代上限留着——但它是护栏，不是判据。」 |
| 1:22–1:30 | `card` | 考点卡 + 「去做这道题 →」 | 「记住这一条，Domain 1 里 27% 的题都建立在它上面。」 |

弹性段落：`diagram`、`compare`、`code`、`card` —— 旁白长了它们就跟着长。
固定段落：两个 `veo` 片段，各 8 秒，中英文共用。

## 7. 视觉方案（已确认）

### 7.1 三层结构

每一帧都是三层叠出来的。分层的意义在于：**只有最贵、最慢、最不可控的那层是 AI 生成的，而它恰好是最不需要准确的那层。**

```
┌──────────────────────────────────────────┐
│  第 3 层  字幕 / 逐词高亮      ← 代码，中英各一套 │
├──────────────────────────────────────────┤
│  第 2 层  图表 / 代码 / 箭头 / 标签  ← 代码渲染，绝对准确 │
├──────────────────────────────────────────┤
│  第 1 层  微缩景观底图 + 运镜   ← Gemini 出图 → Veo 加运镜 │
└──────────────────────────────────────────┘
```

第 1 层**不含任何文字**。这一条是硬性的，收益有三个：

1. AI 画不糊文字了——因为根本不让它画文字
2. 改文案不用重新生成图
3. **中英文共用同一批底图和同一批 Veo 片段，图像和视频成本直接减半**

### 7.2 风格圣经

每条图像 prompt 都要拼上这段后缀，一个字都不改。45 课的一致性全靠它：

```
tilt-shift miniature diorama, handcrafted scale-model figures with matte
painted finish, dramatic warm key light from above, deep charcoal-black
background, shallow depth of field, macro photography, subtle dust motes in
the light beam, cinematic color grade, muted teal and terracotta accents,
photorealistic render, 16:9 --no text, letters, words, numbers, signage,
labels, watermark, ui
```

负向提示里必须写死 `--no text, letters, words, numbers` —— 否则模型会自作主张往场景里加招牌。

### 7.3 Domain 1 的 13 个隐喻

微缩景观最擅长的就是把抽象概念变成看得见的实物。每课一个隐喻，且和任务地点呼应：

| # | 课程 | 隐喻画面 |
|---|---|---|
| 1 | 看信号 | 微缩铁路信号塔，扳道工握着操纵杆，红灯与绿灯 |
| 2 | 三种「输出异常」原因 | 三条断掉的电报纸带并排：剪刀剪断／纸卷用尽／盖了拒绝章 |
| 3 | 拆解合约 | 一份厚合约被裁成三份，分送三个工位 |
| 4 | 招募 Agent | 两个小人：一个被提线牵着走固定路线，一个自己拿着地图 |
| 5 | 行动顺序 | 传送带上的闸门，没盖章的箱子过不去 |
| 6 | 同步突袭 | 港口三台吊臂同时卸货 ／ 对比一台来回跑 |
| 7 | 情报交接 | 隔着毛玻璃递纸条，对面完全看不见这一侧 |
| 8 | 深挖线索 | 小人手里已捧着卷宗，却还派人跑向远处的档案馆 |
| 9 | 矛盾情报 | 法庭上两份证词并排，法官举起「冲突」牌而非偷偷抽走一份 |
| 10 | 证据链 | 证物袋上一串封条，每转手一次盖一个章 |
| 11 | 现场已变 | 工头手里的旧蓝图，与背后已经改建的楼不一致 |
| 12 | 这活儿自己干 | **黄铜天平**：左盘堆满委派手续的碎石，右盘一座小巧完整的村落 |
| 13 | ★断线重连 | 数据中心黑了一半，一根发光的缆绳从 checkpoint 文件牵回来 |

第 12 课正是你发的那张天平图——那个隐喻可以直接用。

### 7.4 第 1 课的实际 prompt

**底图 A（0:00–0:08 开场）**

```
A miniature railway signal tower on a dark tabletop diorama. A tiny
scale-model signalman in overalls stands at a brass lever. One lamp glows
deep red, the other glows green. Fine rain streaks catch the light.
+ 风格圣经后缀
```

**底图 B（0:30–0:38 转场）**

```
Extreme macro of the same miniature signal lamp switching from red to green,
the filament blooming, reflections sliding across wet brass.
+ 风格圣经后缀
```

**代码层叠加**：循环流程图（模型→工具→结果→回到模型）、三种做法的对比栏、`stop_reason === 'tool_use'` 的代码高亮、结尾考点卡。全部矢量渲染，中英文各一套文案，共用同一张底图。

**Veo 运镜**：底图 A 缓慢推近 + 轻微手持晃动；底图 B 微距不动，只有灯丝亮起。两条都是 8 秒。

### 声线（实测存在，非推测）

`voices.list` 确认 en-US 有 33 个、cmn-CN 有 30 个 Chirp3-HD 声线，且下列六个中英文同名：

| | 声线 | 风格 |
|---|---|---|
| 男 | Charon / Puck / Enceladus | 稳重讲师 / 年轻干练 / 低沉叙述 |
| 女 | Zephyr / Aoede / Kore | 清晰明亮 / 温和亲切 / 冷静专业 |

配音输出 **LINEAR16 WAV 而非 MP3**：WAV 的时长可以直接从字节数算出，精确到毫秒、无需解码。
「音频是时钟」这条原则要求时间轴按真实时长铺，所以这里不能用需要解析才能拿到时长的格式。

脚本支持断点续跑（已生成的不重做）和按 beat 重试——中文旁白偶尔会触发 TTS 的「句子过长」限制，
重试即可通过；写中文旁白时多用句号断句可以避免。
